# 100vh 연쇄 타격·대체 벤더 시연

전체 코드는 app_chain_demo.py 한 파일입니다. 다른 로컬 모듈, 외부 DB, 지도 다운로드 없이 실행합니다. 기존 app.py와 조사 데이터 파일은 수정하지 않았습니다.

## 실행

```powershell
python -m pip install "streamlit>=1.66,<2" "plotly>=6,<7"
python -m streamlit run app_chain_demo.py --server.port 8518
```

기본 모드는 API 호출이 없는 테스트입니다. 서버가 준비되면 http://127.0.0.1:8518/ 에서 확인합니다.

## 구성

- st.columns([2,5,3]), 100dvh/overflow:hidden, 3개 패널 고정.
- 좌측 8개 공정 점수, 우회 적용 여부, 정상 복구.
- 중앙 Plotly 3D 구체와 구면 궤적. orthographic 카메라와 구면 좌표를 사용하므로 둥근 구체를 회전할 수 있습니다. 외부 지형 파일이 필요한 Scattergeo 대신 Surface/Scatter3d를 사용합니다. 대륙 윤곽은 코드 내부의 간략화한 시연 선입니다.
- 우측 상단 원인·기존 공급·우회 공급, 하단 이슈 입력. 긴 대화 기록 대신 마지막 입력/응답만 보여 원페이지를 유지합니다.
- 16개 가상 Tier-1 기업, 소재 32개(주/대체), 벤더 32개(주/대체), 공정 8개. make_network의 nodes/tier1/processes 딕셔너리로 확장합니다. SAMPLES 한 행을 추가하면 소재·벤더·코어·대체 소재·대체 벤더가 생성됩니다.
- 모든 기업·위치·관계·가동/대체 효율은 가상 시연 데이터입니다. 각 노드/대체 정의에 status/source/source_year를 붙였습니다. 좌표는 지역 대표 좌표와 겹침 방지 오프셋이며 실제 공장 위치가 아닙니다.

## 계산 정의

1. 소재·벤더·코어의 기존 가용률 = min(직접 가동률, 필수 하위 노드 가용률). DAG를 순회하고 순환/누락을 거부합니다.
2. 코어별 대체 요청 = min(1−기존 가용률, alt_capacity).
3. 대체 벤더 공급 풀 = vendor.capacity × 대체 벤더 가용률. 여러 코어가 같은 벤더를 공유하면 요청량 비례로 나눠 중복 사용을 막습니다.
4. 최종 코어 가용률 = min(1, 기존 공급 + 배분된 대체 공급).
5. 공정 점수 = 그 공정의 필수 코어 가용률 최솟값×100. 전체 점수도 8개 공정의 최솟값입니다.

alt_capacity=.4는 정상 수요의 40%를 대신 공급한다는 뜻입니다. 주 공급이 완전히 끊기면 40점이며, 주 공급 20%가 남아 있으면 20+40=60점입니다. 기본 규슈 샘플의 대체 예약 한도는 .6이므로 100% 중단 시 60점을 방어합니다. 대체 경로의 소재/벤더도 피해를 받으면 우회 공급이 줄거나 없어집니다. 허위 최저점 보정은 넣지 않았습니다.

우회 호는 대체 벤더에서 공정 수요 표시점으로 갑니다. 피해 공장의 가동이 복구된다는 뜻이 아니라, 그 코어의 산출물을 대체 생산해 공정 수요에 전달하는 가상 계약 모델입니다. 피해 원래 경로는 붉은 점선으로 남고 실제 공급된 우회만 Cyan으로 표시합니다. 공정 표시점은 실제 시설이 아닙니다.

## 바로 시연할 입력

- 규슈 소재 100% 중단 → 포토/증착·이온주입/패키징 60점, 우회 3개. 체크박스를 끄면 같은 타격에서 0점.
- 감광 원료 A 공급 80% 감소 → 주 공급20%+대체60%=80점.
- 광학 부품 B 공급 80% 감소 → 주 공급20%+대체40%=60점.
- 대체용 감광 원료 A 공급 100% 감소 → 이전 타격과 누적되어 해당 우회 여력 소실.
- 규슈 복구 → 규슈 대상 타격 해제. 정상 복구 또는 좌측 버튼 → 전체 해제.

이슈는 누적됩니다. 같은 대상에 새 비율을 넣으면 그 대상의 비율을 갱신합니다. 비율이 없으면 100% 중단의 시연 가정을 사용하며 응답에 명시합니다. 테스트 해석은 등록된 이름/ID/지역을 지원합니다. 관세와 미등록 Nokia 공장은 실제 생산 타격으로 변환하지 않습니다. 자연어 해석이 모호하면 등록된 이름을 그대로 사용하세요.

## 발표용 OpenAI

서버 환경의 SUPPLY_OPENAI_ENABLED=1, OPENAI_API_KEY, OPENAI_MODEL이 모두 준비되면 모드에 OpenAI가 추가됩니다. 사용자가 그 모드를 선택한 뒤 제출할 때만 Responses API의 구조화된 해석을 호출합니다. 수학 계산은 Python이 수행합니다. 키는 브라우저에 전달하지 않습니다. 현재 실제 API 호출은 검증하지 않았습니다. 공급 관계·타격 사실을 조사하는 뉴스 검색/시설 검증 기능은 이 단일 파일 시연에 포함되지 않습니다.

## 검증

9개 자동 검사: 정상 100점, 소재→벤더→코어→공정 전파, 우회 60점/해제 0점, 부분 공급+대체 합산, 대체 경로 동시 피해, 공유 벤더 공급 풀 중복 방지, 잘못된 입력/순환 거부, 주/대체 이름 구분, 동적 우회 trace 및 orthographic 카메라. Streamlit AppTest 초기/이슈 적용 모두 예외 0개.

원페이지 UI의 상세 기준은 데스크톱 화면입니다. 좁은 화면은 글자와 지도 가독성이 줄어듭니다. 화면별 검증 치수와 실제 스크린샷은 작업 완료 보고를 참조하세요. 지구본 지역 라벨은 초기 시점에서 우선순위/지리적 간격으로 제한하며, 회전 후 화면 투영 충돌을 실시간 재계산하지는 않습니다. 실제 기업·시설 데이터로 바꾸려면 원본 앱의 근거 체계와 함께 검증해야 합니다.

브라우저 확인: 1440×900 및 1280×720에서 페이지 높이=뷰포트 높이, 8개 점수·우회 토글·입력/적용 버튼이 한 화면에 표시됩니다. 정상/타격/우회 복원, 우회 해제 시 0점 전환을 확인했습니다.
