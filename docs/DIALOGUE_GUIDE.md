# 영향 설명·대응 비교·이슈 대화 사용 안내

2026-10-25 구현. 기본은 테스트 모드이며 외부 API 호출이 없습니다.

## 바로 사용하는 방법

앱 상단 ‘이슈 대화’를 누릅니다. 등록된 국가·기업·소재와 공급 감소율·기간을 입력하고 ‘이슈 분석’을 누릅니다. 해석된 범위, 경로 수, 예상 점수를 확인한 뒤 ‘가정 시나리오를 지도에 적용’을 누르면 전체 보기와 히트맵·병목·영향 설명이 갱신됩니다. 기존 기본 시나리오를 선택하면 언제든 그 시나리오로 돌아갑니다. 새 대화는 대화 초안만 초기화하며 적용된 지도 시나리오는 유지합니다. 기록은 현재 Streamlit 세션 안에서만 유지하며 영구 저장하지 않습니다.

| 테스트 입력 | 예상 동작 |
|---|---|
| ASML 공급 능력 50% 감소, 14일 | 노광 장비 경로 2개, 전체 50점, 포토 병목 |
| 그럼 20%로 바꾸고 30일 | 이전 ASML 대상 유지, 전체 80점 |
| 원인과 대응책 알려줘 | 현재 분석 초안의 투입재·공정·대응 점수를 설명 |
| 프랑스 산소 공급 30% 감소, 7일 | 산소 경로만 선택. 수소 등 다른 프랑스 공급 품목은 제외 |
| JSR 공급 능력 100% 감소, 30일 | 감광재 손실과 재고·대체 비교. 실제 품목/고객 납품은 기존 근거 범위 유지 |
| 트럼프 희토류 관세 20% 부과 | 가정 비용 이슈. 기준 100→120은 관세만 단순 가산한 설명용 지수. 생산 계산 적용은 비활성 |
| 일본 지진으로 Nokia 공장 차질 | Nokia·시설 위치·피해 지역·공급 비중 확인 필요. 일본 전체 공급 중단으로 대체하지 않음 |

테스트 모드는 LLM이 아닌 규칙 기반 해석입니다. 모호한 표현, 새 기업/소재, 방향을 지정한 거래, 복수 비율의 역할은 자동으로 해결하지 않습니다. 한 번에 한 이슈를 입력하고, 복잡한 자연어는 발표용 OpenAI 모드에서 해석할 수 있습니다. OpenAI도 누락된 시설/공급 관계를 실제 데이터로 만들어 넣지는 않습니다.

## 영향 원인과 대응책

지구본 아래 ‘영향 원인 · 대응책 비교’는 현재 지도 조건을 설명합니다. 필수 투입재별로 공급 경로 → 소재 가용률 → 공정 점수를 보여주고 직접 공급·재고·대체 기여를 분리합니다. 현재 조건 / 소모성 재고 +7일 / 대체 공급 가정 / 병행의 전체 점수와 병목을 비교합니다. 장비처럼 기존 재고가 0인 품목에 재고를 새로 만들지 않습니다. 대응 비교가 현재 지도 조건을 자동 수정하지 않습니다. 비용 최적화나 실제 조달 보장은 하지 않습니다.

기존에 정상인 경로의 공급자가 있으면 ‘검토 후보’로만 표시합니다. 그 업체의 추가 물량·등급·인증·납기·전환 비용을 검증한 추천이 아닙니다. 특히 다른 나라를 단순 경유하면 관세가 줄어든다는 가정으로 경로를 만들지 않습니다.

## 발표 때 OpenAI 연결

현재 외부 API는 실행하지 않았습니다. 서버를 실행하는 환경에서 아래 값을 설정한 후 서버를 다시 시작하면 선택 메뉴가 활성화됩니다. 키를 소스·프런트엔드·채팅에 넣지 않습니다. .env 파일이나 Streamlit secrets를 자동으로 읽는 기능은 없으며, 현재 어댑터는 서버 환경변수를 사용합니다.

| 서버 환경변수 | 의미 |
|---|---|
| SUPPLY_OPENAI_ENABLED=1 | OpenAI 연결을 명시적으로 허용 |
| OPENAI_API_KEY | 사용자의 API 키, 서버에만 보관 |
| OPENAI_MODEL | 계정에서 사용 가능한 Responses/Structured Outputs 지원 모델 ID |
| SUPPLY_OPENAI_WEB_SEARCH=1 | 선택 사항. 모델의 웹 검색 지원이 필요하며 ‘공식 자료 조사’ 버튼 활성화 |

환경이 준비돼도 화면의 기본 모드는 테스트입니다. ‘OpenAI · 발표용’을 선택해 분석을 실행할 때 입력 문장·등록 목록·직전 초안이 OpenAI로 전송됩니다. 단순 지도 변경과 테스트 모드 계산은 API를 호출하지 않습니다. 요청 ID 중복 처리를 막아 같은 요청이 화면 갱신마다 재호출되지 않게 했습니다. API 실패/미완성 응답/모델 거절은 오류로 표시하며 이전 초안의 적용 버튼을 남기지 않습니다. store=false로 요청하지만 별도 계정 데이터 정책이나 로그 보관을 면제한다는 뜻은 아닙니다.

OpenAI는 이슈를 구조화하고, Python은 대상 ID·감소율·기간·시설 비중을 검증하고 계산합니다. ‘공식 자료 조사’는 출처를 클릭할 수 있는 조사 메모를 표시합니다. 검색된 문장이 자동으로 시설/경로/생산 감소율로 등록되지는 않습니다. 실제 API 인증·모델 호환성·응답 품질·웹 검색은 시연 환경에서 별도로 검증해야 합니다. 이번 검증은 네트워크 없는 테스트 모드와 API 요청/응답 모의 검사입니다.

공식 API 참고: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [Web search](https://developers.openai.com/api/docs/guides/tools-web-search).

## 지역·공장 계산을 위한 데이터

현재 data/facilities.json은 의도적으로 빈 목록입니다. 실제 공장 정보는 다음을 모두 확인한 뒤 등록합니다.

- 시설 ID·실제 명칭, 등록 기업 company_id, 실제 소재 국가·지역·위도·경도
- 시설 위치 근거 URL, 기준연도, status=출처 있음
- 그 시설이 담당하는 기존 공급 edge_id별 fraction(0 초과 1 이하), 비중 근거 URL·연도

구조는 다음과 같습니다. 이 예시는 형식 설명이며 실제 시설이 아닙니다. 문자열 자리표시자를 검증된 값으로 바꾸기 전에는 앱에 넣지 마세요.

```json
{
  "id": "verified-facility-id",
  "name": "확인된 시설명",
  "company_id": "기존 기업 ID",
  "country": "실제 소재 국가",
  "region": "확인된 지역명",
  "lat": 0,
  "lon": 0,
  "status": "출처 있음",
  "source": "https://공식-시설-자료",
  "source_year": 2026,
  "edge_capacity_shares": {
    "기존 공급 경로 ID": {
      "fraction": 0.4,
      "source": "https://시설별-공급비중-자료",
      "source_year": 2026
    }
  }
}
```

확인된 시설이 어느 경로의 40%를 공급하고 그 시설의 가동이 50% 감소한다고 가정하면, 해당 경로의 감소는 40%×50%=20%이고 가용률은 80%입니다. 기존 국가/기업 이벤트와 겹치면 가용률 최솟값을 사용하고 중복 차감하지 않습니다. 여러 시설의 같은 경로 비중 합이 100%를 넘으면 계산을 막습니다. 지역 이름은 검증된 시설의 region과 일치해야 하며, 지진 반경·진도별 피해 추정은 구현하지 않았습니다. 시설이 있더라도 입력에서 피해 지역/시설을 특정하지 않으면 국가 전체 공장을 자동 선택하지 않습니다.

이 구조는 시설 피해 계산의 확장 지점입니다. 현재 Nokia 시설, 희토류 투입재/경로, 실제 관세 적용 범위, 물류 대체 경로 데이터는 추가되지 않았습니다. 따라서 두 예시의 실제 생산 차질과 실행 가능한 우회 수입 경로를 자동 확정하는 단계는 남아 있습니다.
