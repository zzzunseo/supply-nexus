## 실행

압축을 푼 앱 폴더에서 다음 명령을 실행합니다. `start.ps1`도 같은 폴더에서 서버를 시작합니다.

```powershell
python -m pip install -r requirements.txt
python launch_server.py --port 8517
```

직접 실행할 때도 앱 폴더를 현재 작업 폴더로 사용합니다. `.streamlit/config.toml`의 정적 파일 설정으로
`static/world_110m.json`을 제공해야 Plotly가 외부 지도 서버 없이 바다·대륙·국경을 그립니다.

```powershell
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8517
```

이전 화면 코드는 `app_legacy.py`에 보존했습니다. 기존 조사 데이터·원본 시나리오 엔진·프런트엔드도 유지했습니다.
이전 화면이 필요하면 다른 포트에서 `python -m streamlit run app_legacy.py --server.port 8519`로 실행할 수 있습니다.

## 재고·연쇄·우회 계산

수요가 1인 각 노드를 하루 단위로 위상 순서에 따라 계산합니다. 같은 투입재의 병렬 공급은 정규화 가중 합,
서로 다른 필수 투입재는 최솟값을 취합니다. 각 기업의 공정 문맥을 분리해 웨이퍼→산화→포토→식각→증착→배선→EDS를
직렬 연결하고, 가공 웨이퍼 공급을 통해 패키징으로 전달합니다. 한 기업의 모든 소재를 하나의 AND 노드에 몰아넣지 않습니다.

재고 `B`는 명목 일일 수요 단위입니다. 기존 공급 `P`의 부족분을 `I=min(B,1-P)`만큼 채우고 재고를 차감합니다.
자사 공장의 직접 운전 중단은 원료 재고로 복구하지 않습니다. 생산된 제품의 재고는 제품 노드에서 출하 완충할 수 있습니다.
남은 부족분에 대해 `min(1-P-I, alt_capacity)`를 요청합니다. 대체 풀의 실제 모델 가용량이 요청 합보다 작으면
같은 위상 단계의 요청에 비례 배분하고, 하루 예산에서 배정량을 차감합니다. 여러 단계에서 같은 풀을 사용하면 상류 예약을 먼저 배정합니다.
대체 풀 자체가 타격받으면 해당 우회 공급도 감소합니다.

각 노드의 최종 공급은 `min(1, P + I + 배정된 우회)`입니다. `alt_capacity=0.4`는 정상 수요의 최대 40%를 예약 대체한다는 뜻이므로,
기존 공급 0%일 때 최대로 40점, 기존 공급 20%일 때 60점입니다. 원래 병렬 공급사가 남아 있으면 그 공급은 계속 합산합니다.
단일 필수 경로가 재고·기존 공급·우회 모두 0이 되어야 해당 AND 경로가 0이 됩니다.

점수는 **이슈 마지막 날의 공급 충족도**입니다. 기간 평균은 결과의 `average_scores`, 최초 부족일은 `first_hit`,
일별 기록은 `timeline`에 제공합니다. 공정 점수는 기업별 해당 공정 출력 중 최솟값, 전체는 8개 공정의 최솟값입니다.
관세는 대상 수입재의 전액 과세·전액 가격 전가를 가정한 지수 `100×(1+관세율)`로 따로 표시하며 생산 공급을 낮추지 않습니다.
이 값은 실측 조달 비용·완제품 원가가 아닙니다.

## 사용과 확인 예시

이슈 입력은 누적됩니다. 같은 대상의 새 감소율은 이전 값을 바꾸며, `정상 복구`로 초기화합니다.
예시 버튼은 단일 시나리오를 적용합니다. 기간 컨트롤을 변경하면 모든 활성 이슈의 기간이 함께 바뀝니다.
소재·기업을 함께 지정하면 교집합만 적용합니다. 국가만 입력할 때는 `일본 전체 공급 중단`처럼 국가 전체 가정을 명시합니다.
공장·지진 입력은 특정 시설의 피해 비율을 자동 추정하지 않습니다. 감소율이 없으면 100% 공급 감소 가정임을 답변에 표시합니다.

## UI 및 상태

- 화면은 100vh/100dvh, `st.columns([2,5,3])`와 Plotly orthographic 구면 지도입니다.
- 바다·대륙·국경은 로컬 Natural Earth 기반 세계 지도입니다. 회전·확대가 가능하고 시점을 유지합니다.
- 공정 가상 표시점을 제거했습니다. 공식 주소·지도와 대조한 27개 실제 위치를 등록하고 본사·공장·광산을 구분합니다. 시설 좌표 미확인은 지도에서 숨깁니다.
- 원본 공급 궤적은 부족 시 붉은색/앰버 점선, 실제 모델 배정이 발생한 우회는 파란 선으로 표시합니다.
- 재고로 100을 유지한 공정·투입 노드는 초록색, 일반 정상은 시안, 감소는 앰버, 중단은 레드와 기호로 구분합니다.
- 전체/공정 필터, 국가/기업/소재 연쇄 보기, 아시아/유럽/미주/이슈 시점, 클릭 포커스·해제 버튼을 제공합니다.
- 필터·이슈·계산 결과·가정 변경·제품군·대화 기록은 `st.session_state`에 저장합니다. 새 브라우저 세션이나 서버 재시작에서는 초기화됩니다.
- 대화는 등록된 엔터티의 오프라인 규칙 해석입니다. OpenAI·검색 API를 호출하지 않습니다.
- 상세 데이터·모델 설정은 대화상자로 열어 원페이지 본문의 높이를 유지합니다.

## 확인 결과와 한계

Python 전체 83개 검사가 통과했습니다(연쇄 모델 14개·위치 검증 7개 포함). 원본 44개 동일성, 재고 경계·소비, 대체 40% 계산,
공유 풀 중복 방지, 실제 대체 풀 타격, 연쇄 0점, 제품군 분리, 관세 분리, 입력·복구·오류 처리, Plotly orthographic·우회 선을 확인했습니다.
Streamlit AppTest에서 초기→PR 60→우회 끔 0→7일 재고 100→복구→관세 120/생산100 흐름이 예외 없이 실행됐습니다.
브라우저에서 1440×900과 1280×720의 본문 높이·패널·입력창 표시와 실제 입력 반응을 확인했습니다.

제한: 실제 제조 리드타임·공정 체류/WIP·재고 실측·계약·등급 인증·물류/관세 품목코드·조달 원가·시설 피해를 모델링하지 않습니다.
일별 연쇄 계산은 같은 날 의존성을 전파하며 실제 칩 제조 시간표가 아닙니다. Orthographic는 회전 가능한 구면 투영으로 경로는 표면의 대권을 따릅니다.
Three.js처럼 구면 위 고도·발광·연속 입자 효과가 있는 장면은 아닙니다. 라벨은 우선순위·지리적 간격으로 8개까지 제한하며
임의 회전 후 모든 화면 겹침을 완벽히 제거한다고 보장하지 않습니다. 데스크톱 1280×720 이상을 기준으로 맞췄습니다.
