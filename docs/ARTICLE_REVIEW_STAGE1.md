# 1단계 — 원문 검토와 등록 공급망 조회 연결

2026-10-27. 앱 주소: http://localhost:8517/ (8520도 같은 소스).

## 완성한 범위
오른쪽 ‘기사 붙여넣기 · 원문 검토’에서 제목·출처 URL·본문을 입력하고, 이름 언급 후보를 찾은 다음 사용자가 대상·원문 근거·사건 종류·영향 범위를 검토합니다. 후보는 사건 피해 대상이라는 자동 판정이 아닙니다. 포토레지스트처럼 여러 등록 공급자와 연결되는 표현은 자동으로 모두 적용하지 않습니다.

근거 인용은 제출한 본문과 정확히 일치해야 하며 선택한 대상의 언급을 포함해야 합니다. 검토 단계의 본문은 고정하며 새 본문으로 변경하면 후보 탐색부터 다시 진행합니다. 대상 미연결 상태도 보류 기록으로 유지할 수 있습니다.

저장 후 오른쪽에서 검토 원문과 등록 경로 수를 보고, ‘원문·등록 경로·근거 보기’를 열어 다음을 확인합니다.
- 원문·검토 내용: 입력 URL, 정확한 인용, 사용자 분류와 범위, 고정 원문
- 등록 경로·근거: 공급자·소재·수요기업·공정, 관계 출처, 공급관계 근거/참고 관계/추가 가정의 구분
- 미확인·추가 확인: 독립 사실 검증, 발행·발생 시점의 구조화, 현행 계약·구매 비중·재고·대체 인증·생산 영향

기사의 실제 고객 피해와 현행 품목 계약은 별도 미확인으로 표시합니다. 등록 경로가 없다는 결과도 ‘영향 없음’으로 해석하지 않습니다. 등록 위치가 있는 대상은 지도에서 별도 선택할 수 있으며, 해당 위치가 기사 속 사건 발생 시설이라는 뜻은 아닙니다. 미등록 위치를 만들어내지 않습니다.

## 계산과 분리
기사 검토는 공급 감소율·기간을 임의로 채우지 않고, 계산 후보도 생성하지 않습니다. 기존 시나리오 사건 목록·소재 선택 범위·점수·계산 결과는 유지됩니다. 기존 가정 입력과 시연 예시는 접힘 영역에 분리했습니다. 해당 시나리오 입력의 기본 가정은 그대로이며 기사 분석 결과가 아닙니다. 이전 시나리오 범위 자동 활성화·초기화 문제는 별도 보완 대상입니다.

검토 기록은 현재 세션에 보관되며 JSON으로 내려받을 수 있습니다. 데이터베이스 영구 저장·사건 이력 관리는 아직 연결하지 않았습니다.

## 아직 구현하지 않은 것
- 기사 URL 자동 수집, 기사 사실의 독립 검증
- LLM 또는 자동 문장 의미 분석으로 사건·시설·등급·수치를 추출하는 기능
- 기사 피해 범위와 고객 공급 계약을 대조해 확정하는 기능
- 실시간 뉴스 감시·중복 기사 통합·실제 생산량 예측

이번 단계는 수동 검토를 포함한 하나의 연결된 사용자 흐름을 완성한 것입니다. 이름 일치 후보를 자동 사실 추출이나 AI 분석이라고 표시하지 않습니다. 기존 news/schema.py 및 lifecycle.py는 수치·일자까지 구조화된 향후 검토 사건의 검증용이며, 이번의 미확인 원문 기록을 그 계약에 강제로 끼워 넣지 않았습니다.

## 검증
- 최종 전체 Python 테스트 314개 통과(81.901초), 신규 기사 검토 검증 10개 포함
- 대상 미연결·다중 후보 보류, 허위 인용 거부, 본문에 없는 대상 거부
- 시설 범위 보존, 수치 기본값 미주입, 참고 관계/공급 근거 구분
- URL 형식과 계정정보 제한, 원문·그래프 비변경
- 기존 시나리오·점수·범위 유지, 지도 대상 선택, 근거 상세창 열기
- 같은 출처가 여러 경로에 등장하는 경우의 중복 제어 검증
- 실제 브라우저에서 가상 기사 입력 → 후보 선택 → 인용 → 저장 → 근거 구분·미확인 탭 확인

첨부된 가상 사례와 화면은 기능 검증용이며 실제 JSR 사고를 보도하거나 확인한 자료가 아닙니다.

## 다음 단계 제안
기사의 발행 시점·사건 발생 시점·기업/시설/제품 범위·공급 영향 확인 수준을 구조화하고, 각 값에 원문 근거 또는 미확인 상태를 붙이는 단계가 다음입니다. 그다음 이 입력 구조에 자동 해석 또는 LLM을 연결할 수 있습니다.
